# 蒙皮基础与实时形变执行计划

> 状态：所有实现阶段未开始。阶段编号独立于渲染主线 M 系列。
> [研究入口](README.md) · [资产准备](AssetPreparation.md)

## 1. 依赖与执行顺序

```text
A0/A1 资产与约定 → S0 数据契约 → S1 CPU 数学基线 → S2 动态绘制
                                                      ↓
                                    S3 Vertex shader skinning
                                                      ↓
A2 真实人偶 ───────────────────────→ S4 glTF 角色导入与动画
                                                      ↓
                                    S5 调试、实例与渲染收尾
                                                      ↓
A3/A4/A5 → D0 缓存与数据闭环 → D1 SSDR → D2 压缩播放
                                             ↓
                                    D3 RBF 姿态驱动
                                             ↓
                                    D4 质量与性能评估
                                             ↓
                                    D5 可选动态响应研究
```

在 S2 后可提前做 D0 小缓存回放，但不因此跳过 CPU/GPU 与资产一致性验证。GPU skinning 与动画采样是独立问题：第一版动画采样/FK 在 CPU，顶点蒙皮在 GPU。

## 2. 模块与边界

拟新增 `SkinningSample` 作为基础验证，后续 `CharacterDeformationSample` 复用其能力。算法放独立 API 无关库；DCC exporter、离线 trainer、runtime model 与 renderer 分离。

建议职责（目录名在 S0 评审后确定）：

| 模块 | 职责 |
|---|---|
| animation 数据/函数 | 节点局部姿态、层级全局矩阵、clip 采样 |
| deformation 数据/函数 | palette、LBS、RBF 特征与推理、后续动态状态 |
| sample | 时间/交互、实验切换、发布通道 |
| skinning/deformation recipe | buffer、shader、上传、draw/pass、依赖描述 |
| DCL | 标准资产 skin/animation 解码，不承担每帧播放 |
| 离线 tools | SSDR/RBF 训练、评估、版本化模型导出 |
| RG backend | 通用 GPU 创建、同步、录制；不认识肌肉/布料语义 |

纯算法参数使用 span/扁平数组，持久状态预分配，CSR 表示可变长关系。研究期可使用侧载数据，S4 以有限但正规的 glTF 扩展打通真实角色；不要求实现完整通用动画引擎。

## 3. S0：数据与空间契约

### 工作

- 分离 mesh/rest attributes、skin binding、animation clip（共享资产）与 current pose、palette、播放时间（每实例状态）。
- 定义 parent、局部 TRS、全局矩阵；非 joint 的中间父节点也参与层级计算。
- 定义 skin joint 索引 → node 索引、inverse bind matrices、顶点 joint indices/weights。
- 第一版固定最多 4 影响、LBS、旋转/平移骨骼动画，不支持骨骼非均匀缩放/负缩放。未覆盖资产明确拒绝或离线转换。
- 不强制给所有静态 `dcl::vertex` 增加蒙皮字段；优先可选属性表与专用 GPU 表示。
- 明确 CPU/GPU ABI：整数宽度、矩阵排列、对齐、byte offset、palette 范围、顶点索引基址。

一种约定：输出为当前 mesh-local 空间，使用列向量：

```text
G_node = G_parent * L_node
S_j = inverse(M_mesh) * G_joint(j) * inverse_bind_j
v_local' = sum_j weight_j * S_j * v_bind
v_world' = M_mesh * v_local'
```

这里的世界矩阵必须来自同一实例、同一坐标系。若改用角色局部空间则全套一致转换，不重复乘角色根。inverse bind matrix 从资产语义读取，不默认当前 rest pose 就等于绑定姿态。

### 验收

- 人工构造绑定例子：参考 pose 还原原始网格；单骨骼权重退化为刚体变换。
- 根平移/旋转不二次应用；父节点变换传播正确；非 joint 父节点用例正确。
- 非法 joint、NaN、零权重和、越界 palette 有明确错误/受控修复规则。
- CPU/GPU 输入输出空间写入测试说明。

## 4. S1：CPU LBS 与骨架可检查基线（用户核心实现）

### 工作

1. 程序化两骨骼条带/圆柱，不依赖 DCL 动画。
2. 参数驱动局部旋转，计算全局姿态与 palette。
3. 从不可变参考顶点计算当帧结果，禁止累计变形上一帧输出。
4. 位置 LBS；选定法线近似规则，并可重算法线作几何对照。
5. 预分配输出/scratch；提供暂停、重置与指定姿态的纯函数入口。

验收：纯刚体、参考姿态、混合权重、正反弯曲、根变换、不同父子顺序输入经拓扑排序后的结果。权重非负且归一化；位置有限。使用可手算/合成数据作为 oracle，不用同一实现生成“预期值”。

## 5. S2：CPU 蒙皮结果接入 CGLab（AI 可做框架）

### 工作

- 新 sample/recipe、CMake target、shader 编译流程；先简单着色、深度与相机。
- 静态 index/UV 等与动态 position/normal 的生命周期分开；首版可上传整个交错顶点，后续按测量优化。
- sample 发布持久结果视图到专用帧通道；recipe 使用 RG buffer_upload 更新动态 vertex buffer。
- 初期不把逐帧更新伪装成整资产卸载/重加载；Engine 现有 geometry upload/retire 接口不是动态网格 API。
- 每帧槽或 ring 管理动态输出，复用门限依据 GPU 完成信号；CPU 源数据保持到实际复制完成。
- 暂关闭相机/阴影剔除，避免静态 bounds 干扰；暂不强制阴影。

### 关注点

当前 `update_scene_transforms` 先于 `run_sample_systems`，extract 读取缓存矩阵。若 sample 修改 scene 根变换，需要同帧刷新方案或调整明确的阶段顺序；骨架专用通道不能掩盖根变换延迟。先检查调用语义再改，不盲目交换所有 phase。

### 验收

- 连续播放、暂停、单步、重置、resize 和关闭稳定；固定时间输入对应固定结果。
- 3 frames in flight 下无闪烁、旧帧覆盖；validation 干净。
- 稳态没有逐帧创建 buffer/pipeline/descriptor，也不依赖 device-wide wait。
- 记录 CPU LBS、上传字节/耗时与绘制耗时，暂不承诺性能目标。

## 6. S3：Vertex shader skinning（用户核心 + AI 接线）

### 工作

- 固定参考顶点、权重和索引留在 GPU；每帧上传 palette。
- 支持 shader 中整数 joint indices、权重归一化约定与 palette 范围。
- GPU 法线处理与 CPU 参考规则一致；非均匀缩放另立能力，不能混入首版。
- CPU/GPU 模式切换与差异报告，主 pass 使用相同时间/姿态。

### 当前 RG 约束

`draw_indexed_indirect_row` 目前只有一个 vertex buffer 字段，pipeline 有多 binding 描述不等于 draw 支持任意多流。选择专用交错 GPU vertex 或 storage buffer 侧读蒙皮属性。若侧读，明确 gl_VertexIndex、draw vertexOffset、primitive 顶点基址和 arena 切片之间的关系。不要为第一个例子提前改造完整多流系统。

palette 绑定可复用 bindless storage buffer 机制；每实例有独立 palette offset/count，不以 mesh handle 代替实例 ID。

### 验收

- 相同输入的 CPU/GPU 位置数值对比（调试 readback/验证 pass 可按需添加），按尺度定义绝对/相对容差。
- 法线比较单独记录；与几何重算法线不相同不直接判为位置算法错误。
- 覆盖非零顶点偏移、多个 primitive、palette 偏移、参考姿态与边界 joint 索引。
- 正常播放无逐帧 GPU→CPU readback；验证功能与正常热路径分开。

## 7. S4：受控 glTF skin/animation 导入

### 工作

- DCL 增加 skin 表、skin joint CSR、IBM、node→skin 关联、可选顶点影响数据。
- 增加 animation channel/sampler、时间和值的扁平数据；保留节点默认 TRS 与静态 matrix 语义。
- 从 JOINTS_0/WEIGHTS_0 正确读取整数/normalized 属性；joint 编号索引 skin joints 列表，不是 node 表。
- 先支持选定测试资产需要的 TRS STEP/LINEAR，旋转使用正确的四元数插值；CUBICSPLINE/额外影响集/morph 等若未支持则明确诊断。
- inverseBindMatrices 缺省等格式合法情况按规范处理；不能凭经验填错误绑定数据。
- clip 播放支持指定时间、循环、暂停/重置；时间由采样器决定，不把每个渲染帧当固定动画帧。
- 共享资产与实例播放状态分离；保留完整父链（包括非 joint 节点）。

### 验收

- A1 最小导出与 DCC 在参考/中间/末帧一致，再接 A2 人偶。
- 节点数、skin/joint 数、权重和、IBM 有数据检查；未支持特性报错可定位。
- 无动画的 skin 仍能显示指定静态姿态；无 skin 的旧 glTF 样例行为不变。
- DCL 子仓与主仓测试通过，静态加载回归不引入额外每顶点蒙皮负担。

## 8. S5：展示基础收尾

- 两个共享 mesh 的实例播放不同姿态，证明 palette/CPU 输出不串用。
- 骨骼线、关节选择、权重热图、参考姿态、CPU/GPU 模式与时间显示。
- bounds 从禁用剔除升级到覆盖动画范围的保守 bounds 或动态 bounds，在剔除之前更新；离线范围不能保证任意外推姿态，超范围时回退。
- 阴影/深度与主 pass 应用同一形变。拾取如仍用静态代理，明确显示限制，不宣称精确表面拾取。
- 记录目标 GPU/CPU、构建配置、角色数、顶点/骨骼数和帧预算，再设性能验收阈值。
- 需要多 pass 复用输出/几何法线重建时才加 compute skinning：声明 storage write → vertex/shader read 依赖与输出生命周期；先单队列。

通过 S5 后冻结可复用基础，进入形变研究。不要求此时实现 IK、混合树或角色控制器。

## 9. D0：离线缓存与 ground truth 回放

### 工作

- A3 先用简单袖筒，A4 可用人工 corrective；保持数据来源标签。
- DCC 缓存 → 中间数组 → CGLab 动态顶点回放，保留驱动骨架与时间。
- 按资产文档检查单位、空间、拓扑、稳定 ID、法线/索引与训练划分。
- 可显示参考形状、实际缓存和驱动骨架，支持准确定位到指定时间。

验收：导出回读与 CGLab 对齐；重复导出可校验；坏拓扑/错帧/非有限数据被拒绝。在这一步通过前不调 SSDR 来“修复”数据错误。

## 10. D1：SSDR 离线拟合（用户核心实现）

### 模型

```text
x_hat[i,s] = sum_b w[i,b] * (R[b,s] * x_rest[i] + t[b,s])
minimize sum_{i,s} ||x_target[i,s] - x_hat[i,s]||²
subject to w >= 0, sum_b w[i,b] = 1, R in SO(3)
```

虚拟骨骼是表示形变的刚体变换，不一定是解剖骨骼，也不必构成父子树。一个数据集统一拟合固定 W 与逐样例变换；不能把各动作独立拟合后未经对齐的骨骼编号直接拼成 RBF 标签。

### 执行步骤

1. 已知 W/变换的 LBS 重建及误差函数。
2. 已知 W 求刚体变换：加权拟合、SVD、反射修正与退化处理。
3. 已知变换求非负、归一化权重。
4. 交替优化、初始化、终止判据与迭代日志。
5. top-K 稀疏影响及重拟合，检查稀疏化造成的误差变化。
6. 骨骼数/影响数/初始化种子实验，处理空骨骼和未约束区域。

### 验收

- 合成刚体/已知蒙皮数据恢复；有限数、旋转正交性/行列式、权重约束正确。
- 记录目标趋势；改变稀疏支持等步骤导致的误差变化单独解释，不虚构全流程必然单调。
- 训练表面 RMSE/P95/max 与重点区域误差；比较不同 B/K 的质量与存储。
- 与 Dem Bones 在可比条件下对照，不要求参数逐元素一致（分解可能非唯一）。
- 检查虚拟骨骼变换轨迹是否抖动；表面重建好不代表变换标签适合 RBF。

## 11. D2：SSDR 压缩播放

导出固定参考网格、固定 W、逐帧虚拟骨骼变换，在已验证的 skinning 路径中播放。SSDR 变换已经定义 rest→target 映射，不重复施加真实骨架的 IBM 或 FK；由适配层生成统一运行时 palette。

验收：原始缓存与“真实 SSDR 变换重建”并排/叠加/热图；离线重建与运行时一致；插帧旋转在旋转空间处理，不直接对矩阵元素线性插值。统计原始位置缓存与实际完整压缩包大小（包含 W/rest/索引/模型），不只比较矩阵大小。此阶段称压缩播放，不称新动作泛化或实时模拟。

## 12. D3：RBF 姿态驱动（用户核心实现）

### 输入、输出与拟合

- 输入先局部关节特征（肘屈伸、前臂扭转，按需肩部/激活）；不直接塞全身所有关节。
- 处理角度周期、四元数双覆盖与特征尺度；局部旋转对数只在明确工作范围使用。
- 输出选择虚拟骨骼的相对旋转参数与平移，或低维形变系数；不直接无约束回归矩阵 16 个元素。
- 保持固定蒙皮权重，RBF 预测当帧变换参数。区分 W、RBF 固定模型系数、当帧推理输出。
- 首版固定中心高斯基 + 正则化最小二乘：`min_A ||Phi*A-Z||² + lambda*||A||²`。使用稳定分解求解，不显式求逆；核插值方案若采用则单独记录其方程。
- 核宽度、中心选择、归一化与 lambda 在验证集调节，测试集不参与选参。
- 覆盖外提供距离/置信度指标与淡出到基础蒙皮等回退；不要默认把任意 RBF 输出归一化就能稳定混合。

### 验收

- 训练点、未见中间姿态、边界姿态、未见组合分别报告误差。
- 三路对照：DCC ground truth / SSDR 真实变换 / SSDR + RBF 预测。
- 把表示误差与预测误差分开，不用增加 SSDR 骨骼数掩盖 RBF 问题。
- 连续扫过姿态时无明显跳变；旋转参数分支边界有测试。
- 可增加基础 LBS + RBF corrective/PCA 对照，检查 SSDR 是否值得；修正量的 pre/post-skinning 空间必须明确。

## 13. D4：质量、性能与泛化评估

| 维度 | 必测内容 |
|---|---|
| 位置 | RMSE、P95、max，绝对单位及相对角色尺度 |
| 视觉 | 轮廓、法线角误差、关节/袖口重点区域、接缝 |
| 接触 | 穿透比例/深度、浮空；使用哪个碰撞代理需记录 |
| 时序 | 速度误差、抖动、突停与反向；不只看逐帧平均误差 |
| 泛化 | 完整未见动作、姿态边界、同姿态不同历史 |
| 资源 | 训练时间/峰值内存、完整模型体积、CPU 推理、上传、GPU 形变 |
| 稳定性 | 长循环、切换资产/模式、resize、不同显示帧率 |

先记录 baseline 再冻结可接受阈值，禁止事后放宽阈值宣称通过。近景单臂与远景人物分别设目标。少量穿透可能不影响全局 RMSE，但仍应判视觉问题。各阶段只主张已测得的覆盖范围，换衣物/体型/材质默认需要重新评估或训练。

## 14. D5：可选实时动态响应

仅在用户确认研究重心后立项，两个候选：

1. 姿态/速度/加速度/历史状态输入模型。当前姿态甚至瞬时导数不保证唯一确定布料状态；闭环预测需验长期稳定性、初始化与误差累积。
2. 姿态模型给目标形状，低分辨率 XPBD/其他求解器负责惯性、约束和碰撞，高分辨率表面由固定映射驱动。

推荐优先第二条作为可解释实验，但不预先保证最终质量。先 CPU、简单碰撞体、固定步长，再评估 GPU。明确目标约束与弹性/残差分工，避免形变重复叠加。SSDR 不自动给出质量矩阵、弹性能或低维碰撞求解器。

验收：相同姿态不同运动历史产生不同合理响应；突停、快速运动、碰撞、重置稳定；不同渲染帧率下模拟时间一致；长时间无发散。暂停冻结状态；seek 需重模拟或恢复缓存状态，不允许仅改时间伪造动态状态。

## 15. 验证与阶段记录模板

文档阶段只检查链接、路径、diff 与 Git 状态。代码阶段：

- 算法变化：合成/独立 oracle 单测及对应数据实验。
- DCL 变化：子仓 loader/schema 测试 + 主仓加载回归。
- recipe/RG 变化：相关契约测试 + 新样例与受影响旧样例 GPU smoke，开启 validation。
- 行为变化后按仓库现行脚本运行构建/test；命令与配置以实施时 README/CMake 为准，不复制历史测试数量当作通过证据。
- smoke 只能证明有限帧不报错，不能代替像素、数值、长时间和性能验收。

每阶段完成后填写：

```text
阶段 / 日期 / 主仓提交 / 子仓提交：
资产 ID、hash、DCC/exporter/schema 版本：
实现范围与不支持能力：
构建配置、CPU/GPU、命令：
单测 / GPU validation / 数值与视觉结果：
CPU/GPU/上传/内存测量：
已知问题、下一阶段入口条件：
```
