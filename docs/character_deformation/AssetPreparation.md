# 必要资产准备与数据契约

> 状态：待执行。先准备最小可验证资产，再增加真实角色、布料与肌肉样例。
> 返回 [研究入口](README.md)；实现阶段见 [ExecutionPlan.md](ExecutionPlan.md)。

## 1. 当前优先顺序

| 编号 | 资产 | 必要性 | 交付物 |
|---|---|---|---|
| A0 | 程序化两骨骼条带或圆柱 | S1 必需，可在 CGLab 生成 | 顶点/索引、已知权重、绑定姿态、弯曲参数 |
| A1 | 最小 DCC 两骨骼测试资产 | S4 前必需 | DCC 源文件、glTF/GLB、短动画、参考画面 |
| A2 | 简单已绑定人偶 | 真实角色展示必需 | 源文件、GLB、短动作、许可和导出设置 |
| A3 | 单臂 + 简单袖筒 | D0 前需要 | 固定拓扑皮肤/衣物、绑定/碰撞关系 |
| A4 | 姿态相关肌肉样例 | D3 前按需要 | corrective 或离线模拟缓存，明确来源 |
| A5 | 连续动态缓存 | D1 压缩实验或 D5 前需要 | 完整序列、预滚、驱动参数与模拟配置 |

**先完成 A0–A2 即可，不必等 A3–A5。** A0 不依赖外部资产；A1 验证导出链路；A2 验证实际人物。不要用复杂高精度角色代替 A0/A1 的正确性测试。

## 2. 搜索词与工具选择

- 测试人偶：`mannequin`、`rigged mannequin`、`simple rigged humanoid`。
- 人体基础表面：`human base mesh`；不保证已绑定或有内部肌肉。
- `puppet` 可用于动画绑定语境，`doll` 容易找到玩偶造型。

优先选可以检查骨架、修改权重、固定拓扑和重新导出的资源。不要只下载渲染好的展示文件。

| 工具/资源 | 建议用途 | 注意事项 |
|---|---|---|
| Blender | A1/A2、简单布袖、corrective、脚本导出 | 记录版本与 glTF exporter 设置；视口效果必须与导出一致 |
| MakeHuman / MPFB | 创建简单人形 | 核心/导出许可与额外社区资产分开检查 |
| Blender Human Base Meshes | 人体表面起点 | 不预设已有 rig，更不预设已有肌肉体积和附着 |
| Houdini | 程序化样例、Vellum 布料与肌肉组织 | 学习版使用/导出限制先实测；不能假定 Alembic/FBX 可用 |
| Marvelous Designer | 需要服装版型设计时 | 简单袖筒不必为了它新增一整套工具链 |

工具选择先做一次“10–20 帧导出 → 读回 → 对照”的小试验。若导出能力受版本/许可限制，应改用符合许可的可用流程，不在训练已完成后才发现缓存无法使用。

## 3. A0/A1：最小蒙皮测试资产

建议：一根沿明确轴向伸展的条带/圆柱，两关节，根固定，中间弯曲。权重包括纯根、纯子关节和若干混合区域。

必须保留：

- 唯一命名的 mesh、joint 和 animation；固定参考姿态。
- 两个关节的局部变换、全局绑定矩阵与 inverse bind matrices。
- 每顶点 4 槽影响，未使用槽权重为 0；权重和为 1。
- 恒等/参考姿态、正向弯曲、反向弯曲三个静态检查姿态。
- 一段缓慢弯曲与恢复动画，至少包含参考姿态和中间帧。
- 一个根节点平移/旋转检查，确认角色整体移动不产生二次变换。

建议初期只使用旋转/平移动画、单 skin、单 mesh、简单材质；不使用骨骼非均匀缩放、负缩放、morph、约束驱动的运行时依赖。DCC 中若使用约束，导出前烘焙为目标节点动画。用于对照 LBS 时关闭 DCC 中会改变算法的 preserve-volume/DQS 等选项，记录实际设置。

验收：

- [ ] DCC 内权重与骨骼关系可检查。
- [ ] 导出文件读回 DCC/可信查看器后动作一致，关节数量和映射明确。
- [ ] 参考姿态与弯曲截图保存，注明时间戳/帧号。
- [ ] 不包含必须由 DCC 专有 modifier 才能恢复的未烘焙效果。
- [ ] 后续 CGLab 导入时独立检查 joints/weights/IBM，而非仅确认模型可见。

## 4. A2：真实人偶的选择标准

建议单角色、单套骨架、低至中等复杂度、简单不透明材质。外观无需精美，优先肩/肘/膝容易观察，拥有可靠权重与短动作。最初可用几千到数万顶点，具体数量记录到清单，不作为硬性标准。

动作覆盖：静止参考、屈肘、抬臂、屈膝、角色根平移。不要只用一个全身舞蹈来判断蒙皮正确。

交付前检查：

- [ ] 许可允许使用，若要把资产提交公共仓库，另核对再分发权限。
- [ ] 源地址/作者/下载日期/文件哈希已记录。
- [ ] GLB 中确有 skin 和 animation，而不是只有静态 mesh。
- [ ] 顶点 joint indices 与 skin joints 列表关系明确。
- [ ] 已知是否存在超过 4 影响、额外 JOINTS/WEIGHTS 集、CUBICSPLINE 或其他未覆盖能力。
- [ ] 对不支持特性决定“换资产/受控转换/扩展实现”，不能静默丢弃。
- [ ] 导出再导入后检查比例、朝向、动作、材质和法线。

## 5. A3/A4：单臂、袖筒与肌肉

单臂包括上臂、前臂与可选手部简化体；初期肩固定，主参数为肘屈伸，再加入前臂扭转。袖筒用薄单层网格、固定拓扑，先避免多层、纽扣、复杂缝合与大面积自接触。碰撞体可从胶囊体开始，记录袖口固定/约束区域。

皮肤、衣料独立保存。若布料使用变形后的皮肤作为碰撞体，记录模拟顺序（骨架 → 皮肤 → 布料）和对应时间，不让两者缓存错帧。

肌肉数据分两档：

1. 人工 shape keys / 程序化鼓包：先验证形变学习链路，记录为 corrective。
2. DCC 肌肉/组织模拟：需要内部几何、附着、材料、激活、组织与表面传递，单独验收后替换数据源。

仅有外表皮不代表已具备真实肌肉模拟条件。相同姿态、不同激活若产生不同目标表面，必须记录激活参数；否则先限定固定激活策略。

## 6. 数据契约：正式采样前必须冻结

| 项 | 必须明确的内容 |
|---|---|
| 空间 | 单位、上方向、手性、局部/角色/世界空间、矩阵与四元数排列 |
| 绑定 | 唯一参考网格、绑定矩阵、joint 顺序与 ID |
| 拓扑 | 顶点 ID、索引、三角化、拓扑 hash、焊接/厚度/细分设置 |
| 时间 | fps、实际时间戳、起始时间、预滚区间、驱动与表面同步 |
| 模拟 | 材料参数、步长/子步、碰撞厚度、固定区域、风/重力、初始状态 |
| 特征 | 关节参数、必要的根速度/加速度、重力方向、激活/负载等 |
| 版本 | DCC、exporter、schema、生成脚本版本、随机种子 |
| 划分 | train/validation/test 的序列与姿态 ID；禁止相邻帧泄漏 |

根运动可从几何中消去以获得角色局部表面，但动态模型若需要根加速度、转向或局部重力，必须另外保留相应特征，不能把动力学驱动信息一起删掉。

模拟顶点与渲染顶点常因 UV 接缝、硬法线、材质拆分而不同。必须固定 simulation vertex → render vertices 映射；只比较顶点数量不足以证明对应正确。若使用高低模传递，记录参考三角形、重心坐标与偏移。首版优先同一网格。

禁止每帧重网格、重新焊接或改变细分/厚度设置。每帧校验顶点 ID/索引一致与数值有限。

## 7. 两种采样流程

### 准静态姿态样例

一致初态 → 平滑到达目标姿态 → 等待稳定 → 保存驱动与表面。记录稳定判据，例如最大点速度在指定连续时间窗内低于阈值；数值阈值按尺度实测确定。对易形成多种平衡褶皱的衣物重复同姿态实验，不能默认它是单值函数。

先用局部几十到几百个样例探索覆盖与误差，再自适应补样；不是固定样本数保证成功。增加联合姿态覆盖，不做全身各自由度的笛卡尔积穷举。

### 连续动态序列

从一致初态连续模拟，保留预滚与完整时间序列；包含慢/快动作、突停、反向和同姿态不同历史。按整段动作划分数据集，测试集在调参期间保持隔离。不要随机拆分相邻帧宣称泛化。

## 8. 建议存储与资产清单

源 DCC、原始缓存、处理后数据、运行时包分开保存。离线可用便于分析的数组格式；运行时用版本化 JSON manifest + 明确布局的二进制，不直接序列化带 padding/指针的 C++ 对象。

后续可以创建 `assets/character_deformation/` 放小型回归资产与清单，`tools/character_deformation/` 放生成器；本次仅规划，不创建空实现目录。

每个资产至少填下表：

| 源地址、作者、许可、再分发范围 | 待填写 |

| 源文件 / 导出文件 / SHA-256 | 待填写 |
| 顶点/三角形/节点/joint/skin 数 | 待填写 |
| 动画名称、时长、fps、插值模式 | 待填写 |
| 单位、轴向、绑定姿态、空间转换 | 待填写 |
